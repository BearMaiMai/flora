### 1.4 首页"季节养护"文案修改

**🤔 暂不修改，建议保留"季节养护"**

**理由**：
- "季节养护"是**入口文案**（描述这是按季节推荐的养护重点）

- 可类比：苹果首页"今日推荐" → 跳转到"App Store"，名称不必一致

**如果坚持要改**，可改为「养护知识」或「养护小课堂」，比"种植指南"更贴近"季节性"语境。

**✅ 确认采用 方案 A：前端做截断 + 点击展开/收起**

**实施方案**：

```css
/* care-card-value 改为多行可展开 */
.care-card-value {
  display: -webkit-box;
  -webkit-line-clamp: 2;       /* 默认 2 行 */
  -webkit-box-orient: vertical;
  overflow: hidden;
}
.care-card-value.expanded {
  -webkit-line-clamp: 99;
}
```

```js
// js 加切换
onToggleCareItem(e) {
  const { key } = e.currentTarget.dataset
  this.setData({ [`careExpanded.${key}`]: !this.data.careExpanded[key] })
}
```

### 3.3 提醒完成后的交互

**✅ 确认按"留在原地变状态"实现**

**当前实现**：
- 完成后 `done = true`，加删除线 + 灰色圆点 + 透明度 0.6
- 所属项**仍在列表中显示**（除非用户切到 `pending` 筛选 tab）
- 后端 `complete` 自动生成下一次提醒

**为什么不"消失"**：
- 用户点完后想立即看到反馈，消失会让人困惑（"我刚点的去哪了"）
- 切到「已完成」tab 还能看到历史记录
- 视觉上变灰打勾给予即时确认感

**完整交互流程**：
```
1. 用户点击 → 振动 light + 乐观更新 done=true
2. 后端调用 complete()
3. 0.5s 后 reload 拉到下一次提醒（同 type、新的 nextRemindAt）
4. 用户在「全部」tab 能看到刚完成的（灰色）+ 新的一条（绿色）
```

✅ 当前实现符合此流程。
