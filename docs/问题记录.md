## 二、前端待修问题

### 2.2 首页「季节养护」分类名与后端对不上

**现象**：首页四个养护按钮（浇水技巧/光照管理/修剪指南/施肥方法）都跳转到种植指南页，但全部显示"全部指南"，不会自动筛选对应分类。

**原因**：`miniprogram/pages/index/index.js` 中 `seasonTips` 的 `category` 值用的是英文 key（`water`/`light`/`pruning`/`fertilizer`），而后端 `guide/list` 的 `category` 参数期望中文分类名（`浇水技巧`/`光照指南`/`修剪养护`/`施肥方案`）。

**排查结果**：
- 前端跳转逻辑无误（`goToGuideCategory` 已有 `bindtap`）
- 后端 guide/list 接口无误（传正确 category 可正常筛选）
- 问题是前后端 category 值不一致

**修复方案**（前端改）：
```js
// index.js seasonTips — 把 category 改成中文分类名
{ title: '浇水技巧', category: '浇水技巧' },   // 之前 'water'
{ title: '光照管理', category: '光照指南' },   // 之前 'light'
{ title: '修剪指南', category: '修剪养护' },   // 之前 'pruning'
{ title: '施肥方法', category: '施肥方案' },   // 之前 'fertilizer'
```

### 2.4 百科详情页浇水/施肥提示多了「约」字 + 用错字段

**现象**：花卉详情页养护指南区域显示「约每见干见湿，保持土壤微湿...天浇水一次」，前面多了「约」字，且把文字描述当数字拼进去了。

**原因**：`miniprogram/pages/encyclopedia/detail.js` 第 67-73 行：
- 前端硬编码了「约」前缀（`约每${raw.waterDays}天浇水一次`）
- 用了 `waterDays`（文字描述字段）而不是 `waterInterval`（数字天数）

**修复方案**（前端改）：
```js
// 应该用 waterInterval（数字）来拼格式
const waterText = raw.waterInterval
  ? `每 ${raw.waterInterval} 天浇水一次`  // 7 → "每 7 天浇水一次"
  : raw.waterDays || '根据土壤干湿度灵活浇水'

// 施肥同理，用 fertilizeInterval
const fertilizeText = raw.fertilizeInterval
  ? `每 ${raw.fertilizeInterval} 天施肥一次`
  : raw.fertilizeDays || '生长季薄肥勤施，休眠期停肥'
```

**参考 API 文档**：`docs/API接口文档.md` → flowerService → detail 接口，`waterInterval` 和 `fertilizeInterval` 才是数字天数。

### 2.5 百科详情页「专家问答」显示 [object Object]

**现象**：专家问答区域只显示 `Q [object Object]`，而不是正常的问答内容。

**原因**：`miniprogram/pages/encyclopedia/detail.wxml` 第 123 行：
```wxml
<!-- ❌ item 是 { question, answer } 对象，不能直接渲染 -->
<text class="expert-text">{{item}}</text>
```

**修复方案**（前端改）：
```wxml
<!-- ✅ 取对象的 question 和 answer 属性 -->
<text class="expert-text">Q: {{item.question}}</text>
<text class="expert-text">A: {{item.answer}}</text>
```

后端返回的 `expertAnswer` 是 `[{ question: '...', answer: '...' }]` 数组，数据格式正确。

### 2.6 收藏页爱心图标显示为 heartFill 文本

**现象**：收藏列表页植物卡片上显示"heartFill"文字而非爱心图标。

**原因**：`miniprogram/pages/profile/favorites/index.wxml` 第 59 行：

```wxml
<!-- ❌ heartFill 不是合法的图标名称，组件找不到图标时显示文本 -->
<icon name="heartFill" size="sm" color="#E91E63" />
```

`miniprogram/constants/icons.js` 里的图标名是 `heart` / `heart_filled` / `heartFilled`，不包含 `heartFill`。

**修复方案**（前端改）：查看 icons.js 确认合法名称，将 `heartFill` 改为正确的图标名。

### 2.7 百科详情页「收起」按钮旁显示 chevronUp 英文

**现象**：「收起」文字旁边显示"chevronUp"英文（或"chevronDown"），而非方向箭头图标。

**原因**：`miniprogram/pages/encyclopedia/detail.wxml` 第 95 行：
```wxml
<icon name="{{careExpanded ? 'chevronUp' : 'chevronDown'}}" />
```

图标组件查找 `chevronUp` / `chevronDown`，但 `icons.js` 里只有 `chevronLeft` / `chevronRight`，**没有定义 `chevronUp` 和 `chevronDown`**。找不到图标时回退为显示名称文本。

**修复方案**（前端改）：在 `miniprogram/constants/icons.js` 里补充：
```js
chevronUp: COMMON + 'arrow_top.svg',
chevronDown: COMMON + 'arrow_bottom.svg',
```
或改用已有的箭头图标名称。

### 2.17 缺少内容安全检测（审核被打回，P0 必改）

**现象**：微信审核被打回，提示需要接入内容安全API检测用户上传内容（涉及头像/昵称/反馈文本）。

**后端已完成**：新增 `common/checkContent` 接口，调用微信 `security.msgSecCheck`。

**前端需改**：
- 用户修改昵称前，先调 `common/checkContent` 检测文本
- 用户提交反馈前，先调 `common/checkContent` 检测文本
- 检测不通过（suggest !== 'pass'）时 toast 提示"内容违规，请修改"

```js
// 调用示例
const check = await wx.cloud.callFunction({
  name: 'common',
  data: { action: 'checkContent', content: '用户输入的文字' }
})
if (check.result.code !== 0 || check.result.data.suggest !== 'pass') {
  wx.showToast({ title: '内容违规，请修改', icon: 'none' })
  return  // 阻止提交
}
// 通过检测，继续提交
```

## 四、前端对接指南（本次新增）

### 4.1 guideService 接口

| 接口 | 用途 | 参数 |
|------|------|------|
| `guide/list` | 种植指南文章列表 | `page`, `pageSize`, `category`（可选，不传返回全部） |
| `guide/detail` | 文章详情 | `id`（care_guides 集合的 _id） |
| `guide/featured` | 首页精选文章 | 无 |

**category 可选值**：`入门基础` / `浇水技巧` / `光照指南` / `施肥方案` / `病虫防治` / `换盆教程` / `修剪养护`

### 4.2 reminder/list 新增字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `plantLocation` | String | 植物摆放位置（关联 plants 集合），未设置则为空字符串 |
| `status` | String | `normal`（正常）/ `warning`（24小时内）/ `overdue`（已逾期） |

详情见 `docs/API接口文档.md`
