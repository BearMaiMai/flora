## 二、后端直接实现（6项）

### 2.1 每日小贴士随机化

**现状**：`getHomeData` 固定取 `daily_tips` 按 `date` 倒序第1条。

**改动**：
```js
// 原代码
const tip = await db.collection('daily_tips').orderBy('date', 'desc').limit(1).get()

// 改为随机取1条（使用聚合）
const tip = await db.collection('daily_tips').aggregate().sample({ size: 1 }).end()
```

**注意**：聚合查询不支持 `.where({ isPublished: true })` 过滤，需确保 `daily_tips` 全部已发布，或先过滤再随机。

---

### 2.2 为你推荐随机化

**现状**：`getHomeData` 固定取 `flowers` 前6条（数据库自然顺序）。

**改动**：
```js
// 原代码
const recommend = await db.collection('flowers').limit(6).get()

// 改为随机取6条
const recommend = await db.collection('flowers').aggregate().sample({ size: 6 }).end()
```

**同时**：`flower/recommend.js` 也做同样改动（首页和"为你推荐"页面保持一致）。

---

### 2.3 flower/detail 返回 isFavorite

**现状**：详情页不返回用户是否已收藏该植物。

**改动**：在 `flower/detail.js` 中查询当前用户收藏列表，判断并返回 `isFavorite`。

```js
// 在返回前增加
const { data: users } = await db.collection('users').where({ _openid: openid }).get()
const isFavorite = users[0]?.favorites?.includes(id) || false

return { code: 0, data: { ...data, isFavorite } }
```

---

### 2.4 养护提醒状态计算

**现状**：`reminder/list.js` 只返回原始数据，没有状态标识。

**目标**：根据 `nextRemindAt` 计算每条提醒的紧急程度：

| 状态 | 条件 | 颜色建议 |
|------|------|---------|
| `normal` | 距下次提醒 > 1 天 | 绿色 |
| `warning` | 距下次提醒 ≤ 1 天 | 黄色 |
| `overdue` | 已超过提醒时间 | 红色 |

**改动**：`reminder/list.js` 返回每条记录时增加 `status` 字段：

```js
const now = new Date()
const next = new Date(item.nextRemindAt)
const diffHours = (next - now) / (1000 * 60 * 60)

let status = 'normal'
if (diffHours < 0) status = 'overdue'
else if (diffHours <= 24) status = 'warning'
```

---

### 2.5 添加到花园后自动创建养护提醒

**现状**：`plant/add.js` 只创建植物记录，不创建提醒。用户添加植物后需要手动创建浇水/施肥提醒。

**目标**：添加植物时，根据该植物的 `flower.waterDays` 和 `flower.fertilizeDays` 自动创建两条提醒。

**改动**：
```js
// plant/add.js 中，创建植物后
const { data: flowerData } = await db.collection('flowers').doc(flowerId).get()

// 自动创建浇水提醒
if (flowerData.waterDays) {
  await db.collection('reminders').add({
    data: {
      _openid: openid,
      plantId: res._id,
      type: 'water',
      title: `给${nickname || flowerName}浇水`,
      intervalDays: flowerData.waterDays,
      nextRemindAt: new Date(Date.now() + flowerData.waterDays * 24 * 60 * 60 * 1000).toISOString(),
      isCompleted: false,
      createdAt: db.serverDate(),
    }
  })
}

// 同理创建施肥提醒
if (flowerData.fertilizeDays) {
  await db.collection('reminders').add({...})
}
```

### 2.6 提醒完成后自动计算下次提醒

**现状**：`reminder/complete.js` 只标记 `isCompleted: true`，不创建下一次提醒。

**目标**：完成提醒后，自动根据 `intervalDays` 计算 `nextRemindAt`，更新为下一次提醒时间。

**改动**：
```js
// reminder/complete.js
await db.collection('reminders').doc(id).update({
  data: {
    isCompleted: false,        // 重置为未完成
    nextRemindAt: new Date(Date.now() + reminder.intervalDays * 24 * 60 * 60 * 1000).toISOString(),
    completedAt: db.serverDate(),
  }
})
```

> 注意：这里不是标记完成，而是"完成当前这次，并设置下一次提醒时间"。如果用户想要标记为已完成不再提醒，需要另一个接口（如删除提醒）。

## 三、补充功能（用户没想到的）

### 3.1 plant/detail 返回关联花卉详情

**现状**：`plant/detail.js` 只返回 plants 集合数据，不返回关联的 flowers 数据（如封面图、养护说明等）。

**问题**：前端展示"我的植物"详情时，可能需要同时显示花卉百科信息（如封面图、详细养护指南）。

**建议**：`plant/detail.js` 返回时增加 `flowerDetail` 字段，关联查询 flowers 集合。

---

### 3.2 首页数据聚合优化

**现状**：`getHomeData.js` 每次调用都查 `daily_tips` + `flowers`，没有缓存。

**建议**：
- `daily_tips` 和 `flowers` 数据变化不频繁，可在前端做本地缓存（Storage）
- 后端无需改动，只需接口文档说明缓存策略

---

### 3.3 数据库索引建议

**需要创建的索引**：

| 集合 | 字段 | 类型 | 用途 |
|------|------|------|------|
| `flowers` | `category` | 升序 | 分类筛选 |
| `flowers` | `sortOrder` | 升序 | 排序 |
| `plants` | `_openid` + `createdAt` | 复合 | 我的植物列表 |
| `reminders` | `_openid` + `isCompleted` + `nextRemindAt` | 复合 | 提醒列表筛选排序 |
| `users` | `_openid` | 升序 | 用户查询 |
| `daily_tips` | `isPublished` | 升序 | 已发布筛选 |

---

### 3.4 统一 CATEGORY_MAP

**现状**：`getHomeData.js`、`flower/list.js`、`flower/detail.js`、`flower/recommend.js` 都有独立的 CATEGORY_MAP，内容一致但分散维护。

**建议**：抽离为公共常量文件，如 `cloudfunctions/utils/constants.js`：

```js
module.exports = {
  CATEGORY_MAP: {
    1: '观叶植物',
    2: '观花植物',
    3: '多肉植物',
    4: '果蔬',
    5: '驱蚊植物',
  }
}
```

---

### 3.5 云函数超时配置

**现状**：`common/config.json` 已设置 `timeout: 60`，其他云函数未配置。

**建议**：涉及聚合查询（随机取样）的云函数，超时设为 20-30 秒。
